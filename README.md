# 投資結算管理中心

這是一套可在 Windows 本機執行、也可由 GitHub Pages 線上開啟的投資資料與到期收益結算系統。管理者可以手動新增或由 Excel 匯入投資資料，系統會自動計算到期日，並一次結算所有已到期顧客的淨收益。

## 主要功能

- 一筆投資資料包含：投資人名、投資案名、投資金額、開始時間、持續時間、投資利率、投資淨收益與備註。
- 尚未結算的資料可以編輯或刪除；已結算資料會鎖定，避免歷史被改寫。
- 支援 `.xlsx`、`.xls` 拖曳或選檔匯入，會先自動辨識欄位、逐列驗證並預覽。
- 可從 Google Drive 選取 Excel 或 Google 試算表，下載後沿用相同的驗證、自動補齊與預覽流程。
- 重複資料會安全略過；有任何格式錯誤時不會部分匯入。
- 一鍵找出基準日前所有到期且尚未結算的投資，建立同一批次的不可變快照。
- 結算總表依顧客彙整本金、加權利率、淨收益與有效報酬率。
- 點擊顧客名稱可查看目前批次、完整歷史時間戳，以及每個投資案的本金、利率與獲利。
- 結算報表可匯出 Excel；完整資料可匯出／還原 JSON 備份。

## Windows 一鍵啟動

需求：Node.js 22.5 以上版本。

1. 雙擊 `start-local.cmd`。
2. 系統會開啟 `http://127.0.0.1:4173/admin.html`。
3. 保持命令視窗開啟；完成後按 `Ctrl+C` 停止系統。

也可以在終端機執行：

```powershell
npm start
```

伺服器只綁定 `127.0.0.1`，外部網路無法直接連入。本機資料寫入：

```text
data/investment-manager.db
```

SQLite 資料檔已列入 `.gitignore`，不會意外提交到公開 repository。建議每次大量匯入或結算後，在「備份與設定」下載完整備份。

## 手動新增與結算規則

- 持續時間支援「日」或「月」。月期間會依日曆計算；例如 1 月 31 日加 1 個月會落在 2 月最後一天。
- 投資利率是整期百分比，輸入 `5` 代表 `5%`。
- 投資淨收益是結算的權威金額，可為 `0` 或負數；系統只把「本金 × 利率」當成核對提示，不會覆蓋輸入的淨收益。
- 到期條件：`到期日 <= 結算基準日` 且尚未結算。
- 一鍵結算只彙整淨收益；本金另列參考，不會被誤標成已撥款金額。
- 同一顧客、同一投資案可以有多筆獨立投資，結算時都會逐筆保留。
- 結算完成後，顧客與投資案名稱、本金、開始／到期日、利率、淨收益與結算時間戳都會保存在快照中。

## Excel 匯入格式

在「Excel 匯入」點擊「下載 Excel 範本」可取得標準檔案。必要欄位：

| 欄位 | 範例 | 說明 |
|---|---:|---|
| 投資人名 | 王小明 | 可使用既有名稱或建立新投資人 |
| 投資案名 | 設備租賃 A | 可使用既有名稱或建立新投資案 |
| 投資金額 | 500000 | 必須大於 0 |
| 開始時間 | 2026-08-01 | 支援 Excel 日期與常見日期文字 |
| 持續時間 | 6個月 | 也可填 `180天`；純數字預設為月 |
| 投資利率(%) | 5 | 可填 `5`、`5%` 或 Excel 百分比格式 |
| 投資淨收益 | 25000 | 可為 0 或負數 |
| 備註 | 合約編號 A01 | 選填 |

系統會在各工作表前 20 列自動尋找表頭；若同一活頁簿有多張可匯入工作表，會先阻擋並要求拆成單一工作表，避免只取其中一張而漏資料。匯入前會顯示可匯入、重複略過與格式錯誤筆數。

### 舊版案件分配矩陣

系統也能辨識下列橫向格式，不必先手動改成一列一筆：

| 固定欄 | 後續橫向欄 | 轉換方式 |
|---|---|---|
| 日期、起租案名／同仁、案源、案件金額、參與總額 | 每位投資人各一欄 | 每個正數分配格展開成一筆投資；投資人取欄名、投資金額取該格 |

- 投資人欄遇到第一個空白表頭即結束，右側備註與撥款彙總不會被誤當投資人；若空白表頭或其後方仍有數字資料，系統會阻擋並要求補齊欄名，避免漏匯。
- 原檔若未標示金額單位、持續時間或利率，預覽會要求一次選擇「原值／千元／萬元」、預設期間與預設整期利率，再批次補齊並估算淨收益。
- 備註中有明確的「3 個月」「6%」等條件時只列為候選；必須勾選「優先採用備註辨識候選」才會套用，並在預覽以橘色標示。一般返還日期只保存在備註，不會被誤算成期間。
- 缺少開始日期且無法唯一推斷時，可直接在轉換設定補日期，不必修改原 Excel。
- 若「參與總額」與各投資人欄加總不同，系統會顯示差額並要求明確覆核；確認後以逐位投資人明細為準，不會自行攤平。
- 匯入前必須確認橫向欄名確實代表正式投資人、B 欄可作為正式投資案名；若原表使用縮寫，應先補成歷史報表要顯示的名稱。
- 含公式但沒有快取計算結果的關鍵儲存格會阻擋匯入，並列出位置；請先用 Excel 或 Google 試算表重新計算並儲存。
- Excel 儲存格即使只顯示月日，系統仍讀取底層完整年份；所有轉換結果都會先預覽，尚未按「確認匯入」前不會寫入資料。
- 舊版矩陣會完整列出所有轉換明細，不只顯示前幾筆；每筆保存檔案 SHA-256、工作表、來源儲存格與補齊依據，Google Drive 另保存檔案 ID。同一來源重匯會略過，內容不同時會列為衝突；本機同名檔若重存導致指紋改變，也會先阻擋要求核對，不會直接建立第二份本金。
- 瀏覽器無法取得本機檔案的永久 ID；若同一份本機檔同時「重新儲存又改名」，請先核對系統既有來源或沿用原檔名，避免被視為新檔。Google Drive 檔案有穩定 ID，不受此限制。

### 缺失資料自動補齊

匯入時會先補齊可合理推斷的空白，再執行嚴格驗證：

- 表格中連續資料的投資人、投資案、開始時間、持續時間或利率空白時，可沿用上一列明確值；全空白列會中斷沿用，避免跨區誤套。
- 有本金與利率但缺淨收益時，可用「本金 × 利率」估算淨收益。
- 有本金與淨收益但缺利率時，可反推等效報酬率。
- 有開始日與到期日但缺持續時間時，可換算為持續天數。
- 系統不會憑空猜測投資人、投資案或投資金額；缺少可靠來源時仍會列為錯誤。

所有補齊值都會在匯入預覽以橘色標示，並列出補齊原因，管理者確認後才會寫入。由本金、利率或淨收益推算的數值屬估算；若契約收益另含費用或調整，請在確認前核對原始資料。

## Google Drive 匯入設定

Google Drive 的私人檔案必須由使用者主動登入並選取，無法在網頁載入時靜默讀取。請先在同一個 Google Cloud Project 完成以下設定：

1. 啟用 Google Drive API 與 Google Picker API，並設定 OAuth consent screen。
2. 建立 Web application OAuth Client ID；Authorized JavaScript origins 加入 `https://xieyaozhong.github.io`。本機測試若使用本專案預設網址，另加入 `http://127.0.0.1:4173`。
3. 建立 Browser API Key，限制網站來源為 `https://xieyaozhong.github.io/CASE1-15000/*`，並限制只可呼叫 Google Picker API。
4. 在系統的「備份與設定」填入 OAuth Web Client ID、Browser API Key 與數字格式的 Cloud Project Number。

系統只申請 `drive.file` 權限，僅能讀取使用者在 Picker 中選取的檔案。Google OAuth access token 只保存在目前分頁的記憶體，不會寫入 localStorage、備份或 repository；系統也不需要且不應填入 Client Secret。

Google 試算表會先匯出成 `.xlsx`，Drive 中既有的 `.xlsx`／`.xls` 則直接下載到目前瀏覽器，再交給本機 SheetJS 解析。離線時仍可使用從電腦選檔的匯入方式。

## 開發與測試

不需要安裝 npm 套件；本機伺服器使用 Node 內建 HTTP 與 SQLite。

```powershell
npm test
npm run start:no-open
```

核心測試涵蓋月底／閏年日期、到期邊界、空白欄位、零或負收益、同顧客同案多筆投資、重複結算防護與本金加權利率。

## 線上瀏覽器模式

公開網址：<https://xieyaozhong.github.io/CASE1-15000/>

由 GitHub Pages 開啟時，系統會自動使用瀏覽器 localStorage，手動新增、Excel 匯入、編輯、一鍵結算、顧客歷史與報表匯出都可操作。投資資料只存在目前瀏覽器，不會寫入公開 repository，也不會在不同裝置間同步；請定期在「備份與設定」下載 JSON 備份。

需要 SQLite 持久化時，請由 `start-local.cmd` 啟動，狀態列會顯示「本機 SQLite」。
